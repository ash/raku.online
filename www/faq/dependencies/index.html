What does Raku++ depend on?

Nothing third-party. The rakupp executable links only the libraries that the operating system already has: the C library, the C++ runtime (on Linux and Windows this is linked into the binary), threads, the dynamic loader, and, on macOS, libiconv. It does not link OpenSSL, libcurl, libffi, zlib, ICU, GMP, PCRE, readline, SQLite, libuv or LLVM, and it does not vendor any of them either.

That does not mean Raku++ cannot do HTTPS or talk to a database. It can, but the engine does not do it alone: a module drives the system's own library through NativeCall. The rest of this page lists what is linked, what is written in-house instead, and what the engine loads only when a program asks for it.

Building it #

You need two things:

  • CMake 3.16 or newer
  • a C++17 compiler: Clang, GCC, MSVC or MinGW-w64
cmake -S . -B build && cmake --build build

There is no bootstrap, so you do not need a Raku to build Raku++. Nothing else runs during the build either: no Python, no Perl, no code generator. The Unicode tables are generated C++ that is checked into src/, and the tools baked into the binary (rakupp install, rakupp doc, rakupp upgrade) are embedded by a CMake script. git is optional. When it is present, the build stamps its describe string into $*RAKU.compiler.build.

COMPILERS.md explains which compiler to prefer on each platform and why.

Why it is built this way #

Raku++ ships as one file. You can copy bin/rakupp on its own to another machine with the same OS and architecture, or COPY it into a container, and it runs. The release CI tests a lone copy with nothing beside it. It does not depend on any particular version of OpenSSL or libffi.

There is also less to keep up to date. A TLS stack, its certificate store and its protocol versions are security-critical code that changes often. Raku++ leaves that work to the system's OpenSSL and curl, which the OS updates. If Raku++ carried its own copy, that copy would age with each Raku++ release.

Checking it yourself #

otool -L "$(command -v rakupp)"                     # macOS
readelf -d "$(command -v rakupp)" | grep NEEDED     # Linux
objdump -p rakupp.exe | grep -i 'DLL Name'          # Windows (MinGW binutils)

To check that nothing from the "Loaded only when a program asks" table is linked, search the output for ssl, crypto, ffi, z, icu, curl or sqlite. None of them appear.

Every snippet here is run on both Raku++ and Rakudo and produces identical output; where they differ, the page says so. Written in the rakupp repository. About Raku++.
